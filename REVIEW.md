# Code review

## 1.7.0 — 16.10.2026

Выполнена проверка изменений восстановления загрузок и общего окна состояний. Очередь хранится в SQLite внутри папки назначения, при запуске сверяется с локальными `.part`, готовыми файлами и текущими метаданными WebDAV, а завершённые строки восстанавливают серую пометку. Раздел «Докачка» показывает незавершённые элементы, продолжает допустимые частичные файлы и отображает общий прогресс передачи. Окна «Докачка» и «Ошибки загрузки» используют общий список, выбор строк, фильтры и блок прогресса. Успешные строки удаляются из активного списка, а после ошибки фокус переходит к оставшемуся файлу.

Отдельно проверены оба варианта заголовка `Content-Range`, которые встречаются при работе с Mail WebDAV: `bytes start-end/total` и `bytes=start-end/total`. Проверяются начальная и конечная позиции, общий размер и `Content-Length`; частичный `.part` не публикуется до полного совпадения.

Локальные регрессионные проверки: **92 passed**. Дополнительно успешно выполнены `py_compile`, `uv pip check`, `bash -n run.sh deploy.sh`, запуск `./run.sh --version` (вернул `1.7.0`) и `git diff --check`. Независимое read-only ревью общего компонента и восстановления очереди не нашло воспроизводимых дефектов. Финальная проверка удаления успешно скачанной строки подтвердила отсутствие рекурсии, проблем жизненного цикла и потери выделения.

Ограничения: автоматические тесты используют локальные fake/WebDAV HTTP-серверы и не доказывают поведение конкретного аккаунта Mail.ru или внешнего сервера. Нативные macOS и Windows в этой проверке не запускались.

## 1.6.1 — 15.10.2026

Исправлено ложное отображение штатно остановленных файлов как ошибок: ручная отмена больше не добавляет файлы в `error_jobs`, не открывает модальное окно и не активирует кнопку «Ошибки». Реальные ошибки, возникшие до отмены, по-прежнему сохраняются для разбора и повтора.

Локальные регрессионные проверки: **72 passed**, включая новый headless TUI-тест отмены очереди без отчёта об ошибках.

## 1.6.0 — 15.10.2026

Реализован контролируемый recovery-flow для batch-загрузок: успешные файлы не блокируются ошибками соседних объектов, а временные и постоянные сбои сохраняются в отдельном модальном отчёте. Ручной повтор одного файла, отмеченных файлов или временных ошибок выполняется последовательно с чтением 90 секунд, пятью попытками, backoff 5/15/30/60 секунд и продолжением `.part`; постоянные ошибки автоматически не повторяются. Остановка прерывает ожидание и сохраняет частичный файл.

Локальные регрессионные проверки: **71 passed**. Дополнительно проверены headless-модальное окно с поиском и фильтрами, ручной повтор постоянной ошибки, остановка во время backoff, классификация HTTP-ответов, реальное Range-восстановление и отсутствие двойного учёта возобновлённых байтов.

Независимое read-only ревью через локальный Claude Opus не нашло блокирующих дефектов. Отмеченная им узкая гонка между проверкой и установкой `downloading` устранена: проверка, подготовка списка и захват состояния повтора теперь выполняются под `self.lock`.

Ограничения: реальный аккаунт Mail.ru и нативные macOS/Windows в этой проверке не запускались. Проверки используют локальные fake/WebDAV HTTP-серверы и не доказывают поведение конкретного аккаунта или состояние внешнего сервера.

Локальные регрессионные проверки: **49 passed**. Тесты включают ответ WebDAV с 23 425 файлами и настоящим тайм-аутом чтения на локальном HTTP-сервере, объединение одновременных запросов к одной папке, сохранение частичного результата и повторное использование успешных запросов перед скачиванием. ## 1.2.0 — 14.10.2026

Ревью выполнено 14.10.2026 по исходному коду, тестам и чистой копии проекта.

### Исправленные дефекты

- DAV href декодируется один раз и повторно кодируется только при построении URL; пути с `#`, `?`, `%` и `;` не теряют имя.
- Объекты принимаются только из успешных `207 Multi-Status` propstat и только как прямые дети запрошенного каталога.
- Возобновление связывается с путём, размером, валидатором версии, адресом WebDAV и пользователем аккаунта.
- Полный `.part` снова проходит HTTP-проверку версии; готовые файлы не перезаписываются.
- Публикация на POSIX использует hard-link, поэтому итоговый файл не появляется недописанным; при ошибке `.part` сохраняется.
- Папка назначения блокируется на время batch-загрузки; конфликт служебных имён и выход через локальные имена отклоняются.
- Коллизии регистра, Unicode и имён частичных файлов выявляются до начала скачивания, в том числе на системах без учёта регистра.
- Сканирование размера и проверка свободного места выполняются вне UI-потока; устаревший результат фонового сканирования не возвращает старый выбор.
- Навигация очищает старую таблицу до запроса нового каталога и проверяет пустой курсор.
- Конфигурация не содержит путей конкретной машины, проверяет типы зашифрованного JSON и не выводит credentials.

### Независимая проверка

Claude Opus (`claude-opus-5-5`, настроенный локальный провайдер) прочитал снимок исходников без доступа к инструментам и данным аккаунта. Первый отчёт содержал ложные срабатывания: command injection через `Path.expanduser()`, удаление `.part` после ошибки `os.link` и обход проверки symlink через `resolve()`. Они проверены по коду и регрессионным тестам, затем отозваны при повторном независимом ревью. Подтверждённый риск коллизий регистра/Unicode устранён.

Повторный вердикт по исправленному снимку: **APPROVED**, без воспроизводимых дефектов в заявленной области применения — персональный загрузчик с фиксированным HTTPS-сервером Mail в собственной папке пользователя. Это ревью исходников, не сертификация безопасности и не проверка реального аккаунта.

Нативные macOS и Windows не запускались в этой среде. Windows-ветки блокировки и публикации проверены только статически; недопустимые имена проверены параметризованными тестами. Приложение не настраивает Windows ACL. Перед заявлением подтверждённой поддержки нужен запуск на целевой ОС.
